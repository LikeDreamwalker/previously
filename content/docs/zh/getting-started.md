# 开始使用

Previously 用一条时间轴上的单一、持续的关系取代了聊天线程——你只需出现并交谈，而 Agent 会自行决定每条消息需要哪些过往上下文。

## 界面

固定的 **AppHeader** 横跨每个页面的顶部：左侧是 "Previously" 标志，右侧依次是 GitHub、文档、设置、主题切换和语言切换。无论滚动位置如何，始终可见。

页面是一个垂直滚动区域，从上到下四个部分：

1. **全屏 Hero** —— `"Previously on {你的名字}"` 以电影级文字渐显动画呈现。演示模式下这里换成人格选择器。
2. **吸附的横向时间轴** —— 一排紧凑的日期圆点，吸附在 AppHeader 下方。每个圆点是一个切片；最右端是「现在」节点。
3. **聊天内容** —— 选中「现在」时是实时对话；选中过去的圆点时是历史切片视图。
4. **吸附的输入栏** —— 固定在屏幕底部。

> **关键要点：没有会话列表，没有线程管理，没有"新建聊天"按钮。时间轴本身就是会话列表。**

## 记忆如何在你对话中形成

记忆不是你手动管理的东西——它在你的对话中自动形成。

**切片（slice）**是一个对话片段。当你开始输入时开启，在你活跃期间保持开启，并在静默 30 分钟后关闭。这是唯一的规则。没有容量限制，没有话题切换检测，没有基于机器学习的错误分割。纯粹的时间驱动切片。

每个已关闭的切片写入一个 Markdown 文件：

```
memory/episodic/slices/YYYY/MM/DD/HHMM.md
```

路径即时间戳：年、月、日、以及第一条消息的小时-分钟。文件携带 YAML frontmatter——焦点、摘要、决策、未决事项、情绪基调、标签——由 Agent 每一轮维护。你永远不需要手动标注。

自上而下读过几个月、几年，切片目录就是你的自传。可 git diff、人类可读、可移植。

## 询问你的过去：看回忆如何工作

当你问到涉及过去的事——"我在住房项目上做了什么决定？"或"提醒我上次和 Sarah 聊天是什么时候"——Previously 会跑一次可见的双层回忆，以可展开的卡片渲染在回答上方。

1. **worker 扫描**（约 500 ms，一个廉价模型）——扫描近期切片摘要和线索索引（`memory/episodic/strands.json`）。它返回指向相关切片的**指针**：切片 ID、相关度分数、每个命中的理由。这是快速、近似的扫描。同一次 housekeeping 调用还顺带维护活跃切片的元数据（摘要、标签、未决事项）。

2. **主模型深读**——主模型（你在工具栏选的模型）接收指针，决定通过 `readSlice` 工具完整读取哪些切片。工具调用以内联卡片显示。如果扫描没找到任何东西，模型可以自行探索。

回忆结果以带 History 图标的卡片渲染：

- **收起**：显示回忆查询与命中数。
- **展开**：显示扫描的推理文本、回忆命中列表（切片 ID、理由、相关度百分比）和置信度。

深读期间的工具调用以内联卡片渲染，带人类可读标签：

| 工具 | 你看到 |
|------|--------|
| `recall` | Recalling "..."（回忆中） |
| `readSlice` | Viewing {date}（查看中） |
| `readStrand` | Following "..."（追踪中） |
| `readPreviously` | 正在读前情提要… |

每张卡片有五种视觉状态：**运行中**（spinner）、**已完成**（圆点）、**错误**（红）、**中断**（黄）、**拒绝**（红）。点击或按 Enter/Space 展开查看完整工具输出——CSS `grid-template-rows` 过渡，无需 JS 测高。

消息本身按 Agent 内部执行顺序分三阶段渲染：**思考** → **回忆/工具** → **回答**。你看到 Agent 思考、扫描时间轴、干活、然后回答——全部在同一条消息里。

## 首次使用体验：演示模式

Previously 没有应用内引导向导。取而代之的是一个只读的**演示模式**，把部署变成一次参观。

以 `STORAGE=demo` 运行（或在未设置 `GITHUB_TOKEN` 的服务器上保持 `STORAGE` 未设置），所有 `memory/` 读取都会来自一个内置虚构人格——默认是 **Caleb**，30+ 个切片，跨越 2022 到 2025。头部有一个固定徽章告诉你写的内容不会被保存。写入看起来成功，但从不落进仓库；刷新页面即重置。

在线演示在 [previously-demo.ldwid.com](https://previously-demo.ldwid.com)。它跑完整的双层回忆系统，所以你可以浏览时间轴、翻看过去的切片、自由聊天、观察回忆工作——无需自己部署。

### 开始你自己的时间轴

从演示切到自己的时间轴：

1. 用自己的 GitHub 仓库和 GitHub personal access token（contents 读写权限）部署 Previously。
2. 设置 `STORAGE=github`（或让自动检测做这件事：不设 `STORAGE`，设 `GITHUB_TOKEN`）。
3. 就这些。你输入的第一条消息开启你的第一个切片。

没有账号创建、没有数据库设置、没有种子数据。时间轴从空开始。记忆从你的第一次对话起累积。

## 线索：时间之上的语义层

随着切片累积，Agent 会构建一个轻量关键词索引，叫**线索（strands）**。一条线索是一个主题关键词——比如 `工作`、`家庭`、`住房`——在多个切片中反复出现。文件 `memory/episodic/strands.json` 把每条线索映射到所有携带它的切片。

回忆会扫描线索索引，按主题而非仅按时间新旧找切片。如果你三年里在 30 个切片里聊过「住房」，扫描会通过线索索引找到它们，然后主模型读取实际内容。

## 日常意味着什么

没有仪式。你不需要打开「新对话」。你不需要打标签或分类任何东西。你不需要管理记忆。

- **出现** —— 打开页面。时间轴就在那里，已预加载你最近的过去。Hero 写着 "Previously on {你的名字}"。
- **交谈** —— 输入并按回车。如果已超过 30 分钟，会开启一个新切片。Agent 读取时间轴、扫描相关上下文、然后回应。
- **问过去的事** —— "我对 X 做了什么决定？"或"Y 是什么时候发生的？"worker 扫描摘要和线索索引，主模型读取完整切片，你看着工具卡片出现并落定。
- **滚动** —— 实时聊天上方的吸附时间轴就是你的完整历史。横向圆点，右端是「现在」节点。

循环就是这样。无需设置、无需清理、无需线程管理。只是一段有记忆、且有效的持续对话。
